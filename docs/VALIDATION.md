# 검증 범위

Windows x64 / .NET SDK 8.0.425 / 설치된 반디집 bz 7.47 Beta에서 개발 환경 검증. Release publish는 win-x64 self-contained 단일 EXE이며 외부 UI/테스트 프레임워크 패키지는 없습니다.

## 자동화

최종 검증: 핵심 테스트 **41개 통과**, WPF 설정/기록/저장 암호 렌더 테스트 및 생성된 파일의 실제 Windows 휴지통 이동 테스트 통과, Release 빌드 경고 0/오류 0. 네이티브 Windows 통합 테스트는 일반 사용자 실행 환경에서 수행했습니다. 작업표시줄 아이콘은 디코딩 폭 256px로 확인하고 화면 밖 테스트 창의 표시/렌더를 검증했습니다.

0.1.4 검증: Windows DPAPI 암호화 저장 및 재시작 복원, 손상 암호문 거부, 실제 ZIP에서 틀린 암호 후 한글·공백·따옴표·끝 역슬래시가 포함된 올바른 암호로 해제, 전체 실패 시 원본 보존, 저장 암호 변경/실패 초기화 후 재시도, 실제 파일명 암호화 7z 목록 조회 및 추출. WPF에서는 빈 암호와 중복 암호 거부, 암호 추가/삭제/설정 저장을 확인합니다.

`dotnet run --project tests/AutoExtract.Tests -c Release`는 콘솔 테스트이며 실패 시 1을 반환합니다. 앱 샌드박스나 비대화형 보안 제한 환경에서는 AppContainer/핸들 이동 검증이 실패할 수 있으므로 일반 사용자 Windows 세션에서 실행합니다. 실제 사용자 다운로드 폴더/원본을 테스트 데이터로 사용하지 않습니다. 핵심 테스트에서는 휴지통 대역으로 성공/실패를 주입합니다. UI 통합 테스트는 자신이 생성한 작은 파일 하나만 실제 Windows 휴지통에 보냅니다.

검증 항목: 일반 ZIP과 한글·특수문자, 손상 ZIP, 다운로드 writer 잠금과 재개, 검사 실패 후 동일 내용 억제/내용 변경 재시도, 12개 동시 요청 중복 방지, 폴더/파일명 충돌, 추출 오류 시 원본 보존, 휴지통 실패 후 원본 복구 및 결과 보존, 여러 감시 폴더와 하위 폴더, JSON 설정 재시작 복원, 성공 기록 재시작 중복 억제, 임시 다운로드 파일 대기, 분할 최초 볼륨, ZIP 경로 순회, 처리 중 원본 변경 차단, 취소, 검증된 원본 핸들 이동, 설정 손상 시 중단, **실제 AppContainer 내부 쓰기 허용/외부 파일 쓰기 거부**, 실제 반디집 ZIP t/x, 형식별 분할 family 혼합 방지, 중단된 원본 복구와 충돌 보존, **실제 암호 ZIP 실패**, **실제 분할 7z 생성/추출/전체 볼륨 처리**, **실제 TAR 추출**.

추가로 검사 후 입력 복사본이 변조되면 성공 처리와 원본 휴지통 이동을 거부하는지 확인합니다.

0.1.2 검증: 원본 유지/휴지통 모드의 정상 임시 폴더 정리, 다른 실패 작업 보존, 휴지통 실패 시 보존, 남은 원본/알 수 없는 파일이 있으면 정리 거부, 기록 삭제의 재시작 지속 및 중복 처리 정보 유지, 저장 실패 시 기록 롤백, 진행 중 작업과 기록 삭제 병행 후 새 내역 유지. WPF 테스트에는 기록 전체 삭제 명령 및 빈 기록 화면 렌더를 포함합니다.

0.1.3 검증: 고유 테스트 파이프를 사용해 별도 자식 프로세스에서 활성화 요청을 전달하고 요청 횟수를 확인했습니다. 연속 요청, 잘못된 요청 뒤 정상 요청, 서버 종료와 응답 없는 서버의 타임아웃을 검증했습니다. 샘플 WPF 창을 숨김/최소화한 뒤 기존 ShowSettings 경로로 표시·정상 상태 복원을 확인했습니다. 실제 사용자 감시 프로그램이나 설정을 테스트 대상으로 사용하지 않았습니다. 실제 Windows 작업표시줄 포커스 정책과 로그인 자동 시작의 전체 사용자 흐름은 별도 수동 검증 범위입니다.

0.1.1 회귀 검증에는 디렉터리 항목이 생략된 다단계 ZIP 경로의 실제 추출과 TAR 경로 순회가 추출 대상 밖에 파일을 만들지 않는지 확인하는 테스트를 추가했습니다. 약 3.3GB 사용자 ZIP의 읽기 전용 진단 복사본에서 기존 오류를 재현했고, 검증된 디렉터리를 미리 생성하면 반디집 추출이 완료되는 것을 확인했습니다. 원본을 수정하거나 휴지통으로 보내지 않았습니다.

`dotnet run --project tests/AutoExtract.UiSmoke -c Release`는 실제 WPF XAML과 ViewModel을 로드하고 화면 밖 테스트 창을 렌더링합니다. 설정/기록 화면 PNG와 바인딩 오류 로그를 `artifacts/ui/`에 저장합니다. 바인딩 오류가 있으면 실패합니다. 샘플 경로만 표시하고 감시/자동 실행 등록을 하지 않습니다. 생성한 통합 테스트 파일의 실제 recycle-only Shell 이동도 검사합니다.

## 수동 확인이 남은 범위

0.1.6 검증: 코어 테스트 50개 통과. 실제 AppContainer에서 생성된 Low EXE·DLL을 게시한 뒤 모든 결과 항목의 Medium SID, 격리 SID 제거, 사용자 소유권·수정 권한·상속을 검사했습니다. 게시된 테스트 EXE의 실행과 파일 쓰기, 결과 파일 수정·이름 변경·삭제도 확인했습니다.

- 실제 Windows 트레이 메뉴/더블클릭/닫기 후 상주/명시 종료. Computer Use로 배포 EXE 실행을 요청했으나 앱 실행 승인 시간 초과로 클릭 검증을 진행하지 못했습니다.
- HKCU 자동 실행 등록과 실제 로그아웃/로그인.
- Windows 휴지통에서 사용자가 원래 위치로 복원하는 전체 UI 흐름. 실제 Shell 이동은 생성된 파일로 검증했습니다.
- Windows 10 및 Windows 11 각각의 깨끗한 PC에서 .NET 미설치 상태의 배포 EXE 실행.
- 실물 RAR/EGG/ALZ 샘플, GB급 분할 파일, 장시간 Chrome/Edge/XDM 다운로드 일시정지/재개, 실제 외장 디스크 분리, 실제 디스크 완전 부족.

위 항목들은 지원 의도와 별도로 이 환경에서 실증되지 않은 범위입니다. 실패 시 원본을 보존하는 경로로 설계했지만 모든 Windows/반디집 조합에서 완전 검증된 상용 릴리스라는 의미는 아닙니다.
